# 救急訓練評価アプリ（デモ版）

想定訓練の評価を、スマホ・タブレットからその場で入力・送信できる HTML アプリのデモ版です。
単一の HTML ファイルと Google Apps Script だけで動作し、評価結果は Google スプレッドシートに記録されます。

- **バージョン**：Ver.2.1（デモ用 / 2026年7月）
- **本体ファイル**：`index（デモ用_Ver2.1）.html`
- **受信スクリプト**：`Code（デモ用_Ver2.1）.gs`

**用途**：デモンストレーション、説明会・研修での画面提示、動作テスト。

> このリポジトリはデモ用です。実施隊の選択肢はダミー（○○署 / △△署 / □□署）で、
> 実際の運用データ・所属情報・送信先は含まれていません。
> 利用する際は、後述の手順で自分の環境にセットアップしてください。

---

## 主な機能

- **接触〜病着タイマー**
  接触 / 離脱 / 現場出発 / 病着 の 4 ポイントをワンタップで記録。
  「接触〜離脱」「離脱〜現場出発」の経過時間を自動計算して表示します。
  タイマーは画面上部に固定表示され、スクロールしても常に押せます。

- **基本情報の入力**
  - 実施日（当日を自動セット）
  - 実施隊（選択式：○○署 / △△署 / □□署 ※デモ用ダミー）
  - 部（選択式：1部 / 2部 / 3部）
  - 評価者（氏名）
  - 区分（選択式：指導救命士 / 訓練見取り）

- **大項目評価（4 択）**
  以下 6 つの大項目を **いいね！ / おしい / もう少し / 該当なし** で評価します。
  各項目には判断の目安となる観察ポイントを参考表示（採点対象外）。
  得点化は行わず、4 択の評価そのものを記録します。
  同じボタンをもう一度タップすると選択を解除できます。

  | 項目 | 内容 |
  |------|------|
  | 🏃 活動全般 | プロトコール遵守・現場滞在時間・方針共有・温かい人間愛と思いやりの心をもった対応 |
  | 🔍 観察 | ABCD 評価・事案に応じた観察・初期評価／全身観察の適切性 |
  | 💓 ハイパフォーマンスCPR | 人工呼吸・胸骨圧迫・パルス／モニターチェック |
  | 💉 特定行為等 | 手技・実施順位・滞在時間・IC・医師確認 |
  | 📞 病院連絡 | キーワード・MIST・指示要請・プレゼン・資格説明 |
  | 🤝 説明と同意 | 活動前の説明同意・活動後の説明 |

- **進捗表示・評価凡例**
  ヘッダー右に「○ / 6 項目」と評価済み数を表示。凡例（🟢いいね！ 🟡おしい 🔴もう少し ⬜該当なし）も画面に表示されます。

- **総括コメント**
  自由記述で総合的な評価コメントを入力。

- **送信**
  入力内容を Google Apps Script（GAS）経由でデモ用スプレッドシートへ送信します。

- **次の想定へ**
  送信完了後に「➡️ 次の想定へ」ボタンが表示され、**評価者・区分だけを引き継いで**他の入力をリセットし、続けて次の想定を評価できます。

## 使い方

1. `index（デモ用_Ver2.1）.html` をスマホ／タブレット／PC のブラウザで開く
2. 訓練の進行に合わせてタイマーボタンをタップ
3. 基本情報・各項目の評価・コメントを入力
4. 「📤 評価結果を送信する」をタップ
   （**実施日・実施隊・部** は必須。未入力だと送信できません）
5. 続けて評価する場合は「➡️ 次の想定へ」をタップ

## デモ環境のセットアップ

1. デモ用の Google スプレッドシートを新規作成し、シート名を `評価記録` にする
2. 拡張機能 → Apps Script を開き、`Code（デモ用_Ver2.1）.gs` の内容を貼り付ける
3. `SPREADSHEET_ID` を手順 1 のシート ID に書き換える

   ```js
   const SPREADSHEET_ID = '（デモ用スプレッドシートのID）';
   const SHEET_NAME = '評価記録';
   ```

4. 「デプロイ → 新しいデプロイ → ウェブアプリ」で公開
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
5. 発行された `/exec` URL を HTML 内の `GAS_URL` に貼り付ける

   ```js
   const GAS_URL = 'https://script.google.com/macros/s/.../exec';
   ```

送信は `mode: 'no-cors'` で行うため、ブラウザ側でレスポンスは読めませんが、GAS 側には記録されます。
コードを修正したら、必ず **新しいバージョンとしてデプロイし直す**（同じ URL を保つには「デプロイを管理 → 編集 → 新バージョン」）。

> `GAS_URL` と `SPREADSHEET_ID` は各自の環境固有の値です。
> ファイルを開けば誰でも読めるため、自分の値を入れたまま公開リポジトリへコミットしないでください。

## 送信データ（payload）

| キー | 内容 |
|------|------|
| `submittedAt` | 送信日時 |
| `date` | 実施日 |
| `unit` | 実施隊 |
| `bu` | 部（1部／2部／3部） |
| `evaluator` | 評価者 |
| `evalType` | 区分（指導救命士／訓練見取り） |
| `items` | 各大項目の評価（`{ section: 項目名, value: 評価値 }` の配列。未入力は `未評価`） |
| `timerContact` / `timerDepart` / `timerSceneOut` / `timerHospital` | 各タイマー時刻 |
| `elapsed1` / `elapsed2` | 経過時間（接触〜離脱 / 離脱〜現場出発） |
| `comment` | 総括コメント |

## スプレッドシートの列構成

```
送信日時 / 実施日 / 実施隊 / 部 / 評価者 / 区分 /
活動全般 / 観察 / ハイパフォーマンスCPR / 特定行為等 / 病院連絡 / 説明と同意 /
接触 / 離脱 / 現場出発 / 病着 / 接触〜離脱 / 離脱〜現場出発 / 総括コメント
```

- **得点・最大得点・得点率の列は作りません。** `HEADERS` より右に余分な列があれば自動削除します。
- ヘッダー行は毎回 `HEADERS` の内容で上書きされ、1 行目が固定表示になります。
- `cleanupNow()` を Apps Script エディタから手動実行すると、その場でヘッダーを整形できます。

## 既知の制限

- **区分の列が空欄になります。**
  HTML は `evalType` というキーで送信していますが、`Code（デモ用_Ver2.1）.gs` は `data.category` だけを読んでいるため、区分が記録されません。
  Code.gs の該当行を次のように直すと記録されるようになります。

  ```js
  data.evalType || data.category || '',   // 区分（新旧どちらのキーでも受ける）
  ```

- **送信結果は画面で判定していません。**
  `mode: 'no-cors'` で送信しているため、ネットワークに到達した時点で「送信完了」と表示されます。
  GAS 側でエラーが起きても画面には出ないので、記録の有無はスプレッドシートで確認してください。

- **認証・重複送信の防止はありません。**
  Web アプリの URL を知っていれば誰でも送信できる構成です。
  訓練評価という用途を前提とした割り切りであり、機微な情報の入力には向きません。

## 技術メモ

- 単一ファイルの HTML（外部ライブラリ・ビルド不要）
- 評価項目は HTML 内の `SECTIONS` 配列で定義。項目の追加・変更はこの配列を編集
- 評価の選択肢は `CHOICES` 配列で定義
- 実施隊・部・区分の選択肢は `buildBasicInfo()` 内の `<select>` を編集して増減
- **項目名を変更したときは、Code.gs の `EVAL_SECTIONS` も同じ名前に揃えること**（不一致だとその列が `未評価` になります）
- 画面は最大幅 600px のレスポンシブ。ヘッダー（`#1565C0`）とタイマーバーは sticky 固定
